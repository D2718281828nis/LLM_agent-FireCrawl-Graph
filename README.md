# ИИ-ассистент для анализа клинических рекомендаций

Исследовательский проект демонстрирует, как LLM, клинические рекомендации Минздрава России и граф знаний можно объединить для поддержки оператора телемедицины. Репозиторий содержит два Jupyter Notebook, описание научной новизны и таблицу сравнения агентов.

> **Важно:** проект является прототипом и не заменяет консультацию врача, диагностику или назначение лечения.

## Состав репозитория

| Файл | Назначение |
| --- | --- |
| `Telemed-conf-AI-assistant.ipynb` | Телемедицинский агент на базе Mistral и LangChain: поиск рекомендаций, обход медицинского графа знаний и формирование подсказок оператору. |
| `FireCrawl-CR-site-parsing.ipynb` | Эксперименты с Firecrawl для получения материалов с портала клинических рекомендаций. |
| `scientific_novelty_graph_ai_agent.md` | Описание научной новизны графового подхода. |
| `agent_comparison.xlsx` | Сравнение вариантов ИИ-агентов. |

## Как устроено решение

Телемедицинский агент использует гибридный RAG-подход:

1. `CLINICAL_REQUIREMENTS_DB` хранит подготовленные выдержки из клинических рекомендаций и ссылки на источники.
2. `search_clinical_guidelines_ru` сопоставляет жалобу с подходящими рекомендациями.
3. `MEDICAL_KNOWLEDGE_GRAPH` описывает заболевания, утверждения, методы лечения и отношения между ними.
4. `query_clinical_knowledge_graph_ru` извлекает связанный подграф, а `generate_operator_tips_from_graph` формирует подсказки.
5. `ChatMistralAI` объединяет найденные факты в структурированный ответ для оператора.

Граф помогает показывать происхождение фактов, выявлять противоречащие рекомендациям утверждения и ограничивать генерацию данными из подготовленной базы. Даты и содержание рекомендаций перед практическим применением необходимо сверять с официальным порталом Минздрава России: <https://cr.minzdrav.gov.ru>.

## Безопасная настройка через Google Colab Secrets

Ключи **не хранятся ни в репозитории, ни в `.env`, ни в коде Notebook**. Оба Notebook получают их непосредственно из защищённого хранилища Google Colab через `google.colab.userdata`.

Опубликованные ранее ключи необходимо отозвать в кабинетах Mistral и Firecrawl и выпустить заново: удаление строки из текущей версии репозитория не отменяет ключ и не удаляет его из истории Git.

### Добавление секретов

1. Откройте Notebook в Google Colab.
2. На левой панели нажмите **Secrets** (значок ключа).
3. Добавьте нужные секреты:
   - `MISTRAL_API_KEY` — для `Telemed-conf-AI-assistant.ipynb`;
   - `FIRECRAWL_API_KEY` — для `FireCrawl-CR-site-parsing.ipynb`.
4. Включите переключатель **Notebook access** напротив каждого секрета.
5. Запустите ячейки Notebook последовательно.

Значение секрета не записывается в Notebook и не попадает в Git при сохранении файла. В код передаётся только результат `userdata.get(...)` во время выполнения сессии Colab. Не выводите полученное значение через `print`.

Если секрет отсутствует или доступ Notebook не разрешён, Colab остановит выполнение ячейки. Добавьте секрет или включите доступ и повторите запуск.

### Почему здесь нет `.env`

`.env` может быть приемлемым локальным решением только при строгом исключении файла из Git, но для публичного учебного репозитория он создаёт лишний риск случайного коммита. Поскольку проект предназначен для запуска в Colab, в нём выбран один явный способ хранения ключей — **Colab Secrets**. Файлы `.env` и `.env.example` проекту не требуются.

## Запуск

1. Откройте нужный `.ipynb` в Google Colab (для Firecrawl в Notebook уже размещена кнопка **Open in Colab**).
2. Настройте Colab Secrets по инструкции выше.
3. Выполняйте ячейки последовательно сверху вниз.

Зависимости устанавливаются в первых ячейках Notebook. Секреты привязаны к аккаунту Google и подставляются только во время выполнения; в сохранённый `.ipynb` их значения не записываются.

## Ограничения

- База рекомендаций в телемедицинском Notebook подготовлена вручную и не обновляется автоматически.
- Поиск основан в том числе на строковом сопоставлении и может пропускать синонимы.
- Ответ LLM требует проверки медицинским специалистом.
- Доступность парсинга зависит от API Firecrawl, структуры внешнего сайта и условий его использования.
- Перед обработкой реальных обращений необходимо обеспечить защиту персональных и медицинских данных.

## Рекомендации по безопасности

- не выводите ключи в ячейках и логах;
- не сохраняйте выполненный Notebook, если вывод содержит чувствительные данные;
- используйте отдельные ключи с минимальными правами для разработки;
- регулярно меняйте ключи и отзывайте их при подозрении на утечку;
- перед коммитом проверяйте изменения командой `git diff` и сканером секретов.
