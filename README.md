# ИИ-ассистент для анализа клинических рекомендаций

Исследовательский проект демонстрирует, как LLM, реальные клинические рекомендации Минздрава России и граф знаний можно объединить для поддержки оператора телемедицины. Репозиторий содержит два Jupyter Notebook, описание научной новизны и таблицу сравнения агентов.

> **Важно:** проект является прототипом и не заменяет консультацию врача, диагностику или назначение лечения.

## Состав репозитория

| Файл | Назначение |
| --- | --- |
| `FireCrawl-CR-site-parsing.ipynb` | Собирает реестр клинических рекомендаций Минздрава (`clinical_recommendations_minzdrav.csv`) и извлекает через Firecrawl-агента текст алгоритма действий врача по выбранному ID; Mistral формирует проверяемое резюме. |
| `Telemed-conf-AI-assistant.ipynb` | Телемедицинский агент на базе Mistral и LangChain: ищет рекомендации в реестре из CSV (ground truth), при необходимости вызывает тот же Firecrawl-агент за реальным текстом, обходит игрушечный граф знаний и формирует подсказки оператору. |
| `clinical_recommendations_minzdrav.csv` | Реестр реальных клинических рекомендаций (ID, наименование, дата размещения, МКБ-10), результат работы `FireCrawl-CR-site-parsing.ipynb`. Служит ground truth для второго Notebook. |
| `clinical_recommendation_*_analysis.json` | Аудит извлечения по конкретному ID: сырой текст, полученный от Firecrawl-агента, и резюме Mistral — для сверки с официальным документом. |
| `agent_comparison.csv` / `.xlsx` | Результат сравнения ответов агента "с графом" и "без графа" на один и тот же кейс. |
| `scientific_novelty_graph_ai_agent.md` | Описание научной новизны графового подхода. |
| `.env.example` | Шаблон локальных секретов (копируется в `.env`, который не попадает в Git). |

## Как работает агент

Оба Notebook построены на одном и том же паттерне LangChain — **tool-calling агент** (`create_tool_calling_agent` + `AgentExecutor`), а не на жёстко закодированном сценарии. Это значит:

1. Модели (`ChatMistralAI`) даётся системный промпт с описанием доступных инструментов (`@tool`-функций) и задачи.
2. Агент получает запрос пользователя (жалобу пациента или, во втором Notebook, инструкцию извлечь текст рекомендации) и сам решает, какие инструменты и в каком порядке вызвать — это классический цикл **ReAct** (Reason → Act → Observe), который `AgentExecutor` крутит автоматически: вызывает выбранный инструмент, добавляет его результат в `agent_scratchpad`, снова спрашивает модель, что делать дальше, и так до тех пор, пока модель не решит, что данных достаточно для финального ответа.
3. Ни один инструмент не может «додумать» медицинский факт — каждый либо читает реальные данные (CSV-реестр, официальный документ через Firecrawl), либо детерминированно обрабатывает то, что вернул предыдущий инструмент. Роль LLM — планирование вызовов и связное изложение результата, а не источник фактов.

### Инструменты телемедицинского агента (`Telemed-conf-AI-assistant.ipynb`)

| Инструмент | Что делает |
| --- | --- |
| `search_clinical_guidelines_ru` | Ищет заболевание/МКБ-10 в `registry_df` — реестре из `clinical_recommendations_minzdrav.csv` (746 реальных записей, ground truth). Понимает несколько разговорных синонимов («гипертония» → «гипертенз» и т. п.) и возвращает до 5 совпадений с их ID. |
| `fetch_clinical_recommendation_json` | По ID из предыдущего инструмента запускает **Firecrawl-агента** (тот же сценарий `extract_doctor_actions`, что и в `FireCrawl-CR-site-parsing.ipynb`) — он открывает официальный документ на `cr.minzdrav.gov.ru` и извлекает раздел «Приложение Б. Алгоритмы действий врача» (или разделы диагностики/лечения) в структурированный JSON, без пересказа. ID проверяется по реестру, произвольный URL сформировать нельзя. Результат кэшируется в рамках сессии — повторный запрос того же ID не бьёт в сеть заново. |
| `query_clinical_knowledge_graph_ru` | Обходит `MEDICAL_KNOWLEDGE_GRAPH` — небольшой иллюстративный граф (утверждения/сущности/рекомендации и связи между ними) — и возвращает связанный подграф по проблеме пациента. Это самостоятельный учебный пример, не привязанный к реальному реестру. |
| `generate_operator_tips_from_graph` | Превращает JSON-результат предыдущего инструмента в конкретные подсказки оператору (например, предупреждает об опровергнутых утверждениях или напоминает уточнить сопутствующее заболевание). |

Агент собирается в двух вариантах, чтобы наглядно показать пользу графа:

- **`TelemedicineAnalysisAgent`** ("с графом") — получает все четыре инструмента и просят дать резюме, доказательную базу *и* подсказки оператору на основе графа.
- **`TelemedicineAnalysisAgentNoGraph`** ("без графа") — получает только `search_clinical_guidelines_ru` и `fetch_clinical_recommendation_json`, то есть доказательную базу, но без интерпретации графом.

Оба варианта опираются на один и тот же реальный реестр и один и тот же Firecrawl-агент для текста рекомендации — разница именно в том, что даёт граф: интерпретацию фактов, опровержение мифов и структурированные подсказки, которых без графа нет. Ячейка `Part II - why graph?` запускает оба варианта на одном кейсе и сохраняет сравнение в `agent_comparison.csv`/`.xlsx`.

### Устойчивость к лимитам Mistral API

Цикл ReAct делает несколько LLM-вызовов подряд за один анализ, а сравнительный прогон запускает оба агента один за другим — это легко упирается в `429 Rate limit exceeded`. Поэтому в Notebook добавлено два независимых механизма:

- `_invoke_with_retry` — реактивный повтор: при 429 ждёт (по заголовку `Retry-After`, если он есть, иначе экспоненциально нарастающая пауза) и повторяет вызов до 5 раз, не роняя весь прогон.
- `InMemoryRateLimiter` у `TelemedicineAnalysisAgentNoGraph` — проактивное ограничение именно этого агента (не чаще одного запроса в 6 секунд, без всплесков), поскольку он всегда стартует сразу после первого агента и первым упирается в лимит.

### Как устроен `FireCrawl-CR-site-parsing.ipynb`

1. Реестр на `cr.minzdrav.gov.ru/clin-rec` не имеет постраничной навигации — только переключатель «Строк на странице» с опцией «Все». Notebook кликает по нему через Firecrawl, **сверяет счётчик «X из Y» на странице** и повторяет попытку с бэкоффом, если переключение не применилось — иначе можно молча получить только первые 5 записей.
2. Все строки разбираются локально через `pandas.read_html` (без LLM — быстрее и без риска, что модель «прочитает» таблицу неточно) и обрабатываются партиями с прогресс-баром, с проверкой количества ID на каждом шаге.
3. Для выбранного пользователем ID Firecrawl-агент (`extract_doctor_actions`) извлекает «Приложение Б» или ближайшие релевантные разделы прямо с официальной страницы, в структурированный JSON.
4. `ChatMistralAI` формирует резюме **только по извлечённому тексту** (без внешних знаний) с явными разделами: цель, действия врача, условия принятия решений, красные флаги, наблюдение, что проверить в оригинале.

Даты и содержание рекомендаций перед практическим применением необходимо сверять с официальным порталом Минздрава России: <https://cr.minzdrav.gov.ru>.

## Настройка секретов: Google Colab и локально/VS Code

Ключи в код и в Git **не вписываются**. Notebook сам определяет среду выполнения и берёт секрет из подходящего места:

```python
try:
    from google.colab import userdata
    IN_COLAB = True
except ImportError:
    IN_COLAB = False
    from dotenv import load_dotenv
    load_dotenv()
```

- **Google Colab** — секреты хранятся в Colab Secrets (значок ключа на левой панели) и подставляются через `google.colab.userdata` только во время выполнения сессии.
- **Локально / VS Code** — скопируйте `.env.example` в `.env` и впишите значения. `.env` заблокирован в `.gitignore` (`.env`, `.env.*`, кроме `.env.example`) и не может случайно попасть в коммит.

Нужны два секрета:

- `MISTRAL_API_KEY` — для `ChatMistralAI` в обоих Notebook;
- `FIRECRAWL_API_KEY` — для Firecrawl-клиента в обоих Notebook (сбор реестра, извлечение текста рекомендации).

Если секрет отсутствует, `require_secret(...)` останавливает выполнение понятной ошибкой с подсказкой, где его добавить — вместо того чтобы упасть глубже в стеке на первом сетевом вызове.

**Если ключ где-либо засветился** (чат, скриншот, публичный коммит) — считайте его скомпрометированным и немедленно отзовите/перевыпустите в кабинетах Mistral и Firecrawl. Удаление строки из репозитория не отменяет ключ и не убирает его из истории Git.

## Запуск

1. Сначала выполните `FireCrawl-CR-site-parsing.ipynb` сверху вниз — он создаст `clinical_recommendations_minzdrav.csv`, который служит ground truth для второго Notebook. Без этого файла `Telemed-conf-AI-assistant.ipynb` останавливается с понятной ошибкой при инициализации.
2. Настройте секреты — Colab Secrets (см. выше) или локальный `.env`.
3. Выполните `Telemed-conf-AI-assistant.ipynb` сверху вниз: он загрузит реестр, соберёт агентов и прогонит сравнение "с графом" / "без графа" на тестовом кейсе, сохранив результат в `agent_comparison.csv`/`.xlsx`.
4. Сверяйте извлечённый текст и резюме с официальным документом по ссылке, которую печатает Notebook (`source_url`).

Зависимости устанавливаются в первых ячейках каждого Notebook.

## Ограничения

- Поиск в реестре основан на подстроковом сопоставлении и заранее заданных синонимах — может пропускать формулировки, которых нет в списке.
- `MEDICAL_KNOWLEDGE_GRAPH` — небольшой иллюстративный граф для демонстрации самой идеи, а не полная база медицинских знаний; он не привязан к реальному реестру.
- Извлечение текста рекомендации идёт через LLM-агента Firecrawl — это реальный сетевой запрос (секунды, иногда больше) и расход кредитов Firecrawl; результат зависит от структуры и доступности официального сайта.
- Ответ LLM в любом случае требует проверки медицинским специалистом и сверки с оригиналом документа.
- Перед обработкой реальных обращений необходимо обеспечить защиту персональных и медицинских данных.

## Рекомендации по безопасности

- не выводите ключи в ячейках, логах или сообщениях чата;
- не сохраняйте выполненный Notebook, если вывод содержит чувствительные данные;
- используйте отдельные ключи с минимальными правами для разработки;
- регулярно меняйте ключи и отзывайте их немедленно при малейшем подозрении на утечку;
- перед коммитом проверяйте изменения командой `git diff` и сканером секретов — особенно файлы, которые выглядят как данные (CSV, JSON), а не как код.
